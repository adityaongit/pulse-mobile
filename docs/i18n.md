# Adding copy to Pulse

Every user-facing string goes through i18next (`src/i18n`). The plan and the reasons are in `docs/i18n-plan.md`.

- **Keys.** Add the English text to `src/i18n/locales/en/<namespace>.json` (the namespace is the area, see the plan's table) and read it with `useTranslation("ns")` in a component or `i18n.t("ns:key")` elsewhere. camelCase, two levels at most, named by meaning. Register a new namespace in `src/i18n/config.ts` (`NAMESPACES`, `resources`) and `types.ts`.
- **Plurals.** `key_one` and `key_other` with `{{count}}`; never `n === 1 ? … : …`. Other languages add the categories their grammar needs.
- **No concatenation.** One sentence is one key with `{{placeholders}}`; word order differs by language. Rich text uses `<Trans>`.
- **No module-level copy.** A constant evaluated at import stays in the first language. Catalogues keep keys and resolve at use.
- **No words in `src/core`, `src/pipeline` or SQLite.** The engine returns codes; the query turns them into text.
- **Glossary.** Pulse, Pulse Age, Health Connect, Recovery, Strain, Sleep Performance, HRV, units and the other names in the plan stay English in every language.
- **Checks.** `pnpm test` runs `src/i18n/i18n.test.ts` (same keys, placeholders, plural forms, glossary). `pnpm lint` flags literal text in JSX.
- **Language and formats.** The choice lives in AsyncStorage `pulse.language` (`src/i18n/language.ts`); dates and numbers use `src/lib/locale.ts`.
